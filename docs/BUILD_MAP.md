# Master build map

The schedule and plan for the whole prototype. The two detailed maps hold the step-by-step instructions for their tracks:
[`BUILD_MAP_CLAIMS.md`](BUILD_MAP_CLAIMS.md) (phases C0 to C10) and [`BUILD_MAP_FORENSICS.md`](BUILD_MAP_FORENSICS.md)
(phases F1 to F10). This file says **who builds what, in what order, when it must connect, and what to cut.**

The reasoning behind every rule here is in the [Bible](SATYAPAN_BIBLE.md); its decision log (D1 to D30) explains the choices.

## 0. Fill these in first

| Setting | Value | Why it matters |
|---|---|---|
| Event window | _fill in_ hours (this map assumes **48**) | Every hour figure below is scaled to it |
| Team size | _fill in_ (this map assumes **4**, one per lane) | One person per lane keeps ownership clear |
| Productive hours per person | window × 0.7 (this map assumes about **34**) | Sleep, meals, debugging and meetings are real |
| Capacity | people × productive hours (about **136**) | Compare with the Tier 1 total in section 3 |

All hours are **estimates**, not measurements. If capacity is below the Tier 1 total, use the cut ladder in section 4 before
starting, not at hour 40.

**Why audio is Tier 1 and the pulse classifier is not.** Forwarded video is heavily compressed, which is where a pulse signal
fails first, while voice notes are a main channel and pretrained audio detectors exist. So the pulse path is kept as a gated
signal with a panel (FO-2 to FO-6, FO-9), and its classifier and slices (FO-7, FO-8) move to Tier 2 until the audio track is
green.

**Tier 1 total: 41 + 37 + 35 + 32 = 145 hours.** Against the assumed capacity of 136, this is over. Use the cut ladder.

## 4. Cut ladder

Apply in this order until Tier 1 fits capacity. Each line says what you lose and what you keep.

| Order | Cut | Hours saved | Running total | You lose | You keep |
|---|---|---|---|---|---|
| 1 | Triage scorer, use first-in first-out (PL-6) | 3 | 142 | Priority ordering | Everything else |
| 2 | Media clustering (PL-4); text clustering only | 3 | 139 | Near-duplicate media grouping | Text dedupe, cache |
| 3 | One fewer source adapter in PL-5 (two instead of three) | 2 | 137 | Breadth of sources | Official source plus fact-check source |
| 4 | CL-10 drills reduced to the five most likely | 1 | 136 | Rare cases | Common failures |
| 5 | FO-9b live heart-rate check | 1 | 135 | One demo moment | Pulse panel |
| 6 | **Drop the video pulse path** (FO-2 to FO-6, FO-9a) | 19 | 116 | Pulse evidence | Audio, claims, provenance, ledger |

Cuts 1 to 4 reach exactly 136, with no slack. That is too tight, because estimates are rarely high. Take cut 5 as well. Then
decide cut 6 at the end of hour 12: if the walking skeleton (G1) is late or a lane is behind by more than a few hours, drop
the pulse path and spend the hours on audio calibration and the evaluation. **Never cut:** the walking skeleton, the
contracts, the ledger, the gate, the abstain logic, the audio quality gate, the drills for source failure and bad uploads, or the
claim sheet. They are what the rubric scores and what keeps the demo alive.

If the window is shorter than 48 hours or the team smaller than four, cut 6 happens at once, then in this order: the second
source adapter, query expansion, the guard (last, it is a hallucination control).

## 5. Contracts, frozen at hour 4

Create `src/satyapan/schemas/` and `tests/contract/test_schemas.py`. All lanes code to these. Changing one after hour 4 needs
all four owners' agreement and a version bump.

```python
class Post(BaseModel):          # ingest output
    id: str; source_id: str; url: str; author_hash: str
    text: str; lang: str | None; media: list[MediaRef]
    posted_at: datetime; fetched_at: datetime

class Claim(BaseModel):         # claims input and output unit
    id: str; post_id: str; text_en: str; text_orig: str
    span: tuple[int, int]; lang: str; translated_by: str | None

class Evidence(BaseModel):      # see claims map for Passage and SupportResult
    role: Literal["supports", "contradicts", "context"]
    source_id: str; url: str; fetched_at: datetime; tier: str
    passage: str; passage_sha256: str
    support_prob: float | None; model: str; model_sha256: str

class Verdict(BaseModel):
    id: str; target_id: str; kind: Literal["claim", "media"]
    label: Literal["SUPPORTED","REFUTED","MANIPULATED","AUTHENTIC","INSUFFICIENT"]
    evidence: list[Evidence]; flags: list[str]     # e.g. CONFLICT, TRANSLATED, GATE_FAILED
    # validator: empty evidence forces label = INSUFFICIENT
    # allowed flags: CONFLICT, TRANSLATED, GATE_FAILED, SYNTHETIC_SUSPECTED, EDITED_REGION, STALE_SOURCE

class DetectorResult(BaseModel):  # from forensics map section 4
    detector: str; version: str; abstained: bool
    score: float | None; quality: QualityReport; evidence: dict

class LedgerEntry(BaseModel):
    seq: int; prev_hash: str; hash: str; created_at: datetime
    kind: str; payload_sha256: str; payload: dict; code_version: str
```

**API endpoints**

| Method and path | Does |
|---|---|
| `POST /verify/text` | Accept text or a post URL; returns a job id |
| `POST /verify/media` | Accept an upload with size and type limits; returns a job id |
| `GET /verdicts/{id}` | Verdict, evidence, flags, agent trace |
| `GET /ledger/{seq}` and `GET /ledger/verify` | An entry; result of re-walking the chain |
| `GET /health/sources` | Each source, last success, last error, age |
| `GET /denials` | Gate denials with reasons |

**Queue.** Start with a job table in Postgres, claimed with `SELECT ... FOR UPDATE SKIP LOCKED`, behind a `Bus` interface. It is
real, durable and needs no extra service. Swap in Redpanda only if lane 1 has finished everything else.

## 7. Working rules

| Rule | How |
|---|---|
| One trunk, short branches | Branch per work package, merge when CI is green, rebase daily |
| Definition of done | Code, tests, the module page in `docs/modules/`, the claim-sheet row, and the status mark in the README |
| No hardcoding | The CI checks in the README's no-hardcoding table; a red check blocks merge |
| Fixtures only in tests | Anything under `tests/` may use recorded data; nothing under `src/` may |
| Integration is continuous | After G1 the end-to-end test `tests/e2e/test_text.py` runs on every merge against live sources |
| Every claim is measured | A number in a slide must exist in `docs/claim-sheet.md` with its command |
| Cross-review | Each pull request reviewed by the owner of the module it touches |
| Daily 10-minute check | Each lane states: done, next, blocked, and whether its gate is at risk |

**End-to-end tests** (`tests/e2e`, marked live): text claim in English; text claim in Hindi; duplicate submission; image upload;
video upload good quality; video upload degraded; source down; non-allowlisted domain request; corrupt upload.

## 9. Questions every member must answer alone

Each person should answer these about any lane, from the module pages, without notes:

1. What happens to a post from arrival to verdict, in order?
2. Why can the system return `INSUFFICIENT`, and where in the code is that guaranteed?
3. What does the verifier say, and what does it not say?
4. Why does the quality gate exist, and how were its thresholds chosen?
5. What can a pulse tell you, and why does it never decide alone? Why are two audio detectors run, and what happens when they disagree?
6. What does the gate deny, and how does the agent behave when denied?
7. How would you prove a ledger entry was changed?
8. Which numbers in the claim sheet are measured, and which are not claimed?

Run a mock Q and A at hour 44, each person answering about someone else's module.

## 10. Risks

| Risk | Trigger | Response |
|---|---|---|
| A live source is unavailable or restricted | `probe_sources.py` fails at H2 | Drop it from `sources.yaml` at once; say so in the claim sheet and the demo |
| Dataset access is slow | No reply by H12 | Use the datasets already available; report the narrower evaluation honestly |
| Verifier too slow on the demo machine | `bench_verifier.py` shows seconds per passage above budget | Use the smaller model; reduce `k`; rely on the cache |
| Pulse path is near chance across datasets | FO-8 gate (Tier 2) | Show pulse as quality-gated support only; spend freed hours on audio |
| Audio detectors collapse on compressed or Indian-language audio | False-fake rate above target in FO-18 | Gate fails those conditions; show the by-condition matrix; do not claim detection there |
| A model card's numbers do not reproduce | PL-11 results far from the card | Report ours, note the gap, and say the card figures are the authors' |
| fairseq install breaks | FO-20 setup exceeds one hour | Drop AntiDeepfake; the two ONNX detectors are the product |
| Image classifiers fail on recompressed or non-face photos | False-synthetic rate above target in FO-23 | Gate those conditions; show the matrix; keep TruFor's map as the image visual |
| TruFor container will not run, or needs a GPU you lack | FO-24 exceeds half a day | Drop to classifiers only; say so; its licence is nonprofit and informational only |
| A licence summary is wrong | Page and note disagree, as with the SDXL face detector | Record both in `docs/licences.md`; use the stricter reading |
| Licence terms block a model | CC BY-NC-SA or missing licence on a needed component | Swap behind the `Detector` interface; note the terms in `docs/licences.md` |
| Fake test audio misused | A real person's voice appears in a manifest | Remove it; use consenting teammates or generic synthetic voices only |
| Translation errors damage Hindi results | Language slice far below English | Report it; flag translated verdicts; do not hide the slice |
| Integration slips | G1 or G2 missed | Freeze features, assign two people to integration, cut by the ladder |
| API key or quota exhausted mid-demo | Rate-limit errors in the health panel | Cached verdicts stay readable; show the typed error; switch source |
| Rule breach by accident | A fixture or copied block appears in `src/` | CI blocks the merge; revert at once |
| Licence problem | A dependency or model has restrictive terms | Check at C0 and FO-1; keep a swappable interface; note it in the README |
| Team member ill or absent | Lane has no owner | Reviewers named in the ownership table take over, using module pages |
