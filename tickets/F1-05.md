## Goal

Turn a post's text into atomic, decontextualised claims with a check-worthiness flag, using the live Gemini API and a schema the model must follow.

## Done when

- `src/satyasutra/llm/gemini.py` is a small client: model id and timeout from config, budgets from F1-02, retry on 429 with the delay the API gives, one typed error per failure class. The key is read from the environment and never logged.
- `src/satyasutra/claims/extract.py` sends a post and returns `Claim` objects validated by the schema in `schemas/core.py`. A response that fails validation is retried once, then returns no claims and records the reason; it is never repaired by guessing.
- Non-claims (opinion, question, greeting) come back with `NOT_A_CLAIM` semantics, not dropped silently.
- `tests/unit/test_extract.py` uses a local HTTP server that speaks the Gemini response shape (the shape comes from the API, checked by the contract test) to cover: valid JSON, invalid JSON, 429 then success, timeout.
- `tests/contract/test_live_extract.py` (marked contract) extracts claims from one real post fetched live in the test and asserts the output validates.
- `python scripts/extract_live.py --seconds 30` prints post text next to the claims extracted, from the live stream.

## Notes

Hindi and English both appear in the stream. This ticket does language ID only as a field; translation and screenshot reading are Phase 2.
