## Goal

Find out now which heavy packages install and run on this machine's Python 3.14, before any ticket depends on them. Where one does not, decide the fallback once: a separate service on Python 3.11 or 3.12 behind an HTTP boundary.

## Done when

- `python scripts/check_env.py` tries each package below in a throwaway virtual environment, never the project one, and writes `docs/env_matrix.md` with one row per package: installed (yes/no), imported (yes/no), one tiny real operation ran (yes/no), seconds, and the failing step when any.
  - torch (CPU, and CUDA if the RTX 4060 is usable)
  - onnxruntime
  - MiniCheck (the package or the model route the Claims map names; record which)
  - MediaPipe
  - faster-whisper
- The script lists which of Python 3.11 and 3.12 are installed (`py -0`) and, for every package that failed on 3.14, repeats the check there.
- `docs/env_matrix.md` ends with a decision per package: **run in-process on 3.14**, or **service on 3.x** with the port, the request shape and the reason.
- `tests/unit/test_check_env.py` covers the report writer and the failure classification with no network.

## Notes

Installing is real work on the real machine; nothing here is mocked. If a package needs a download of more than a few hundred MB, say so and ask before fetching. Weights are not part of this ticket, only the packages and a tiny operation (for example, a 2x2 tensor add, an empty ONNX session, a MediaPipe import).
