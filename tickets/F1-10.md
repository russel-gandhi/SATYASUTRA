## Goal

Replace paid reverse image search with our own index of images that fact-checkers have already examined, plus Wikimedia Commons for provenance, matched by perceptual hash so a recycled or recompressed image is recognised.

## Done when

- Candidate sources are added to `config/sources.yaml` as `unverified`, then probed by `scripts/probe_sources.py`: fact-checker RSS or Atom feeds the team picks (at least three publishers in different languages, found from real Fact Check API results in F1-06, not from memory) and the Wikimedia Commons API (needs the `FORGE_CONTACT` User-Agent from F0-09).
- `src/satyasutra/provenance/fingerprint.py` computes SHA-256, pHash and PDQ for an image and for its horizontal flip. The PDQ implementation and its licence are checked and recorded in `docs/licences.md` before it is added as a dependency.
- `src/satyasutra/provenance/index.py` stores hashes in SQLite with: source URL, publisher, review date, the fact-checker's rating text and the retrieval time. **Images themselves are downloaded transiently, hashed, and discarded; only hashes and links are stored.**
- `python scripts/build_index.py` fetches the live feeds, downloads the images they reference, and fills the index. Re-running adds only new items.
- `python scripts/match_image.py <file-or-url>` returns the nearest indexed items with their Hamming distances, or says there is no match.
- `tests/unit/test_fingerprint.py` generates test images in code (gradient and noise images with Pillow) and checks: a resize, a JPEG recompression and a horizontal flip stay within the configured distance; an unrelated image does not.
- A measurement script reports, on a live sample of Wikimedia Commons images, the false-match rate at the configured distance. The distance threshold is chosen from that table and stored in `config/thresholds.yaml`, with the command that produced it.
- `docs/provenance_index.md` states what the index can and cannot say: a match means "this image appeared in a fact-check", not "this claim is false".

## Notes

Respect each site's terms and robots rules and the rate limits in config. Fetching feeds and images is live data work; do not commit downloaded images. A match is a lead for provenance, never a verdict by itself; that rule lives in the verdict rules, not here.
