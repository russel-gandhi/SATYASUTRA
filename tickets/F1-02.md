## Goal

Measure what the team's Gemini key can really do, so budgets in config come from observation and the agent is never designed around guessed limits.

## Done when

- `python scripts/measure_gemini.py` runs against the live API with a hard cap on total calls (the cap is read from `config/policy.yaml`, not coded) and writes `docs/gemini_limits.md` with, for each model tried:
  - requests per minute observed before the first 429, and the retry delay the API reports
  - the quota names and values the error body states, when it states them
  - median and 95th percentile latency for a short structured-output call, with the sample size
  - tokens per call and cost class (free or paid, as the API reports it)
- It tries `gemini-3.5-flash-lite` first and re-tests `gemini-3.8-flash` with a 60 second timeout and three attempts, recording the timeouts that spiked on 2026-10-31.
- Observed per-minute and per-day limits are written into `config/policy.yaml` budgets with the date measured; the client in `src/satyasutra/llm/` (F1-05) reads them.
- `tests/unit/test_measure_gemini.py` covers 429 parsing and the call cap against a local HTTP server.

## Notes

Stay inside the free tier. If the script would exceed the cap, it stops and says so. It never prints the key, and the key stays in the environment.
