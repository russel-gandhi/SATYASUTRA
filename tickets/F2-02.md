## Goal

Group re-encoded copies of one image into a single cluster, with velocity, so a viral image costs one audit. This is the media twin of the text clusters from F1-08.

## Done when

- `src/satyasutra/fastclock/media_cluster.py` clusters `Fingerprint`s by PDQ distance (the smaller of plain and mirrored, as the index does), with the same velocity and distinct-author counting as text clusters, and the same eviction by idle time and cluster cap from `config/runtime.yaml`.
- The cluster distance is its own entry in `config/thresholds.yaml`, with a note saying how it was chosen. Start from `image_match_pdq_distance` (40) and keep it only if a live capture agrees; **clustering errs differently from matching** (a false merge hides a variant), so the choice is checked by reading real near-pairs, not copied.
- A search over many clusters is not a full scan once the cluster count passes the size where it matters: the ticket measures the per-image cost at 100, 1,000 and 5,000 clusters and either shows the scan is fast enough or adds a multi-index lookup, and records the numbers.
- `tests/unit/test_media_clusters.py` generates images in code: a resize, a JPEG recompression and a horizontal flip of one image land in the same cluster; two unrelated images do not; velocity counts distinct authors; idle clusters are evicted.
- `scripts/cluster_live_media.py --seconds 120` prints the top image clusters from the live stream (size, authors, posts per minute, one example post URL each).
- A post with text and an image ends up referenced by both a text cluster and a media cluster, and the result for the post is a list (Bible Part 3.1), not one number.

## Notes
