## Goal

The fast clock runs continuously inside the service: Bluesky posts flow through normalise, fingerprint and cluster, the ranked clusters are served over HTTP, and live counters show it working. This is "clusters ranked by velocity", the second gate sentence of Phase 2.

## Done when

- `src/satyasutra/fastclock/worker.py` runs the ingest stream into the fast clock as a background task owned by the app (started and stopped with it), reconnecting on a dropped stream with the existing backoff. It is **off unless enabled in `config/runtime.yaml`**, so the API and its tests start without network.
- `GET /fastclock/top` returns the top clusters: size, distinct authors, posts per minute, authors per minute, first and last seen, one example post URL per cluster. Author hashes are never returned (Bible D27).
- `GET /fastclock/stats` returns live counters: posts per minute, posts seen, exact repeats, clusters now, clusters evicted, per-post processing time (median and p95), stream reconnects, last event age.
- The worker never blocks on a slow consumer: if processing falls behind the stream, it drops the oldest posts and counts them (`dropped`), and says so in the stats, instead of growing memory without limit.
- `tests/unit/test_fastclock_worker.py` uses a local websocket server speaking the Jetstream shape (as `test_jetstream.py` does) and checks: counters move, `top` is ordered by distinct authors per minute, a dropped connection reconnects, a slow processor causes counted drops, and stopping the app stops the task and leaves none behind.
- `tests/contract/test_live_fastclock.py` runs the worker against the real Jetstream for a short window and asserts non-zero posts, a stats p95 below the per-post target in `config/slo.yaml` (F2-06; until that file exists, the number is only reported), and a clean shutdown.

## Notes

The counters feed the demo's sources panel and F2-06's table, so name them once here and reuse them. Do not call any model from the worker.

## Closed
