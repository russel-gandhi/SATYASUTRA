## Goal

Prove that a LangGraph run can stream node events live through a FastAPI Server-Sent Events endpoint, because the agent trace panel in the demo depends on it.

## Done when

- `src/satyasutra/agent/trace.py` turns a compiled graph's streamed updates into typed trace events (node started, node finished, tool call, error) with a monotonic sequence number.
- `GET /trace/stream?job=<id>` returns `text/event-stream` and sends each event as it happens, not after the run ends.
- `tests/unit/test_trace_sse.py` runs a three-node graph with a deliberate 0.2 second delay in each node and asserts, over a real local HTTP connection, that the first event arrives before the last node finishes.
- A second test closes the client mid-run and asserts the server stops sending and holds no open task afterwards.
- The result, including time to first event on this machine, is written to `docs/spikes.md` under a new row.

## Notes

The graph here is a plain test graph. The real agent graph is a later phase, but its node shape must match: `planner`, `tools`, `fuse`, `draft`, `verify`. If streaming through LangGraph proves unreliable on Python 3.14, the fallback is a plain loop that emits the same events; record that decision in `docs/spikes.md` rather than hiding it.

## Closed

- Date: 2026-10-31
- Evidence: 269 unit tests pass (8 in test_trace_sse.py over a real uvicorn HTTP connection, stable over 3 runs); guard ok. First event arrives before the last node finishes; median 16 ms to first event (min 3, max 31, 15 runs) on a 620 ms run. Closing the client mid-run stops the run: open-stream counter back to 0, later nodes never ran, no tasks left. langgraph 1.2.18 streams fine on Python 3.14, no fallback needed. Not tested: many clients, a proxy, Last-Event-ID resume, the real agent graph.
