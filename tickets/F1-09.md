## Goal

The walking skeleton: one call takes a live post and returns a cited verdict, and a ledger row proves what was decided and from which evidence.

## Done when

- `POST /verify` accepts a post (text, or a Bluesky post URI that the server fetches live) and returns the claims, each with its verdict, label, confidence, citations and a `ledger_seq`.
- Every verdict, with its evidence ids and the code version, is appended to the ledger, idempotent on the claim text hash and evidence set. `/ledger/verify` stays `ok: true` after a run.
- `GET /ledger/{seq}` returns the entry for the verdict just made.
- `curl -X POST /verify` on a real post, taken live from the stream in the same test run, returns a verdict, and a post with no fact-check hits returns `UNVERIFIABLE_YET` rather than an invented label.
- `tests/unit/test_verify_api.py` covers the route with the extraction and lookup stages replaced by local servers speaking the real response shapes; `tests/contract/test_walking_skeleton.py` (marked contract) runs the whole path live.
- The Phase 1 gate in `docs/PHASES.md` is ticked with the date and the evidence line.
