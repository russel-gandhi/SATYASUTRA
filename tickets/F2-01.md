## Goal

Posts that carry images produce a `MediaRef` and a fingerprint (SHA-256, pHash, PDQ, mirrored PDQ) so images can be clustered and looked up in the debunked-image index. Today ingest keeps text only ("Embedded media is Phase 2", `ingest/jetstream.py`).

## Done when

- `parse_event` fills `Post.media` with one `MediaRef` per embedded image (`kind: image`, mime, size when the record gives it, `source_url` the public CDN URL). The URL form is **confirmed against a live post before it is coded**, by fetching one and checking it returns an image; a record with a malformed embed is counted in `IngestStats` and skipped, never guessed.
- `src/satyasutra/ingest/media.py` downloads an image transiently (size cap, rate spacing and User-Agent from config, reusing `provenance.feeds.download_image`), returns a `Fingerprint`, and discards the bytes. A failed or oversized download is a counted skip, not an exception that stops the stream.
- Ingest records how many posts carried images, how many were fetched, skipped (and why) and the median fetch time, in `IngestStats`, so the cost of media is known before it is turned on by default. Media fetching is off unless `ingest.fetch_media` is set in `config/runtime.yaml`.
- `tests/unit/test_ingest_media.py` feeds `parse_event` records shaped like the live ones (captured and quoted in the test) and a local image server, and checks: one image, several images, a post with an external link card only (no image), a missing blob, an oversize image.
- `tests/contract/test_live_ingest_media.py` (marked contract) takes real posts from the live stream until it has one with an image, fetches it and asserts a valid fingerprint comes back.
- The ticket's closing evidence states the live share of posts with images and the measured fetch cost.

## Notes

Images are fetched only for the fingerprint and thrown away; the database never holds them (same rule as F1-10). Do not add media to `Post.text`. Video is out of scope here (keyframes are a later ticket).
